# ADR-0017：模版资源批次采用数据库中的 YAML 声明

状态：已接受（2026-11-12）；目录兼容与普通 Project 保留条款由 ADR-0018 替代。

依赖交付更新（2026-11-13）：`@openagentpack/sdk@0.10.0` 正式版本已提供本决策要求的
公开合同，Kit 改用精确版本与 lockfile 完整性校验，移除原 vendor 归档及补丁。

## 背景

模版向导只需要一次性创建资源并保存远端引用。目录项目引入了声明文件布局、Build、源码版本库和文件 state，
使 Kit 必须维护与 SDK 目录实现相关的细节。客户仍通过表单操作，不需要额外的 YAML 编辑界面。

## 决策

- 新批次使用 YAML 引擎，期望配置、SDK state 与成功证明按 `draft_id` 保存在 SQLite。
  每批只维护当前 YAML，Kit 修订号用于乐观并发和计划失效，不保存 YAML 历史。
  此存储是临时资源声明与 SDK 执行账本，不是模版历史、Provider 事件库或远端记忆内容镜像。
- SDK 通过公开的字面正文解析入口校验声明，提示词和初始化记忆正文不按文件路径或环境变量重新解释。
  SDK 的原有目录、单文件及 CLI 默认解析行为不变。新链路不初始化 SDK 源码目录，不执行目录 Build 或源码版本管理。
- SDK 管理 state 语义。Kit 的 `StateBackend` 使用公开内存管理器，读取提供隔离副本，写入按 SDK 保存调用
  持久化检查点。网络等待期间不持有 SQLite 事务，沿用单实例和批次互斥约束。
- File 和 Skill 内容保存在独立、受控上传暂存。声明使用相对来源，计划绑定暂存内容清单与哈希，
  执行前复核；不接受浏览器指定的服务端路径。
- Provider 凭据显式传入运行时。Vault 值仅留在本批服务端内存，声明保存随机引用；不写入进程全局环境、
  YAML、state、回执或日志。重启后未发布值仍需重新添加。
- 发布使用完整本批资源的 SDK `create-only` scope，差异来自 SDK。Kit 绑定主体、批次、revision、
  YAML 哈希和 SDK 审阅计划；执行前在批次互斥保护下重新规划、校验，匹配后执行同一计划。
  未确认不写远端；修改已有远端 Agent 继续另存新 Agent，不增加同 ID 升版能力。
- 只有 SDK 完整成功才保存独立成功证明，再完整验证六类绑定并保存最小回执。收尾使用 SDK state 或完整成功证明，
  不能凭部分 state 推断成功。回执持久化后清理 YAML、state、证明和上传暂存；清理失败单独重试。
  已知执行前失败允许重新 Plan；部分成功、结果未知或重启中断禁止自动重发。
- 新控制面入口为 `resource-drafts/:name/resources`，复用已有操作 DTO 的配置字段，去除源码路径字段；
  前端只使用批次 ID、声明与计划，不调用 Build。旧 `project_name` 字段仅保留兼容别名。
- 旧记录迁移为目录引擎，保留原 SDK state 和成功证明，继续通过兼容适配恢复、完成或放弃；不自动转换未知结果。
  普通 Project 的源码、Build、state、版本与发布合同保持原样。ADR-0014 的所有权、一次性关闭和禁止跨批次复用仍生效。

## 后果

Kit 对 SDK 的依赖收敛为公开声明、state 和执行接口，不再为新模版批次维护 SDK 源码布局。
SQLite 新增临时声明与 state 存储，模版长期记录仍只保存引用和展示配置。SDK 的新增能力以可安装归档包锁定，
归档来源与重新构建方法登记在 vendor 中；正式 SDK 版本具备同等合同后可替换依赖来源。

本决策不提供跨进程断点续发、多实例写协调或从历史模版引用重建 SDK state。
