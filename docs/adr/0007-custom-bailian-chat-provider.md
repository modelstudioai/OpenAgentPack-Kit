# ADR-0007：ChatProvider 接入自建百炼后端

第 3 项的六请求回调接入方式已被 [ADR-0008](./0008-stream-request-provider-chat.md)
取代；其余事件、恢复、审批与 SDK 边界继续有效。
五方法合同在 [ADR-0009](./0009-provider-message-transform.md) 中扩展了可选消息转换策略，
原有五方法调用继续兼容。

## 背景

业务方可能已有接入百炼 Managed Agent 的后端，只需要 Kit 的消息状态与组件能力。
要求其复刻整个 Kit Server 会增加无关耦合；只替换请求 URL 又无法处理原始百炼 SSE、
独立发送与订阅、完整历史恢复及工具审批。

## 决策

1. 在 core 定义五方法 `ChatProvider`：订阅、发送、停止、审批查询、审批提交全部必需，
   复用现有参数与返回类型，事件合同仍为 SDK `SessionEvent`。此名称表示前端到业务后端
   的会话接入，不引入第二个上游 Provider。
2. 保留 `useChat(sessionId)` 与 Kit Server 默认行为；新增
   `useChat({ sessionId, provider })`，显式 Provider 优先且不要求 KitProvider。
   `createKitChatProvider(client)` 提供默认适配，KitClient 保持结构兼容。
3. 在 `@openagentpack/kit-core/bailian` 单独导出 `createBailianChatProvider`。通过六个请求
   回调接入自建后端的原始 SSE、历史、发送、停止及审批。调用方负责 URL、应用身份与响应
   包装；Kit 负责解帧与生命周期，原始事件归并只调用 SDK `session-events` 的公开纯转换器。
4. 每次原始流连接先订阅并缓冲，确认上游已就绪，再读取完整历史并合并实时流，最后通知
   Controller ready。初连与重连均全量重建，不假定百炼原生 SSE 存在 Kit 传输游标。
5. 未完成历史没有分片水位，不能直接与新 delta 相加；由 SDK 保留已知展示与身份并等待
   完整快照。不能证明历史与实时业务状态顺序、同 ID 快照冲突无版本依据，或内容分片尚未
   关联消息身份时显式失败，不误判为空闲。
6. Controller 统一调度重连；失败只恢复订阅，不自动重发消息或审批。停止与拒绝分别使用
   正式后端操作，不采用静默 no-op。自建后端负责权限和审批有效性校验。

## 理由

请求接入与消息状态分离后，同一组 hooks 和组件可服务两种部署形态；百炼事件语义仍有唯一
实现。沿用五项完整会话能力，可以保持发送就绪、远端停止和工具审批的业务约束。
独立子入口允许默认 Kit 链路继续使用原有依赖与流协议。

## 后果

- 原始流后端除透传外，还需提供完整升序历史和真实上游就绪保证。只返回 HTTP 200 或等到
  首条业务消息都不足以完成空闲 Session 的初始化。
- 重连代价随历史增长；超时、分页循环或缓冲超限明确失败，不截断历史后宣布 ready。
  恢复中不承诺逐字连续，最终正文以 Provider 完整快照为准。
- 创建 Session、列表与文件仍由调用方后端提供；本次不增加 Kit Server 操作或改变 wire 协议，
  不将单次 POST 返回一轮 SSE 作为内置模式。
- SDK 需要公开浏览器纯转换入口，已有服务端接口、脱敏与截断默认值保持不变。候选包验证
  和正式依赖发布、干净安装分别记录，未发布能力不能作为已发布 npm 能力宣传。

## 备选方案

- 要求自建后端完全实现 `/api/kit/*`：保留为可选部署方式，不作为复用 hooks 的前提。
- 在 Kit 复制 SDK 的原始分片累加器：形成两份百炼转换规则，拒绝。
- 为所有模型服务商建立通用请求与消息框架：缺少第二个真实数据面合同，超出本次范围。
- 允许省略停止或审批、以空实现填充：会使 UI 表示与 Provider 执行状态失配，拒绝。
