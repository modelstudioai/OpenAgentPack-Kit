# ADR-0013：模版配置版本与关联目录原子同步

状态：已接受（2026-10-30）。

## 背景

已保存模版需要支持持续编辑并保留每次保存的配置。员工后续使用最新配置，管理列表无需展示
版本号。远端 Agent 版本只描述 Provider 元数据，无法代表环境、文件、记忆、密钥库与展示文案
组成的完整模版；上架时复制一次配置也无法跟随模版编辑。

## 决策

- 使用独立的本地整数版本，初始为 1，每次编辑成功保存递增；旧模版迁移为第 1 版。
- `kit_templates` 保留当前配置及版本，`kit_template_versions` 以 `(template_id, version)`
  保存不可变完整配置快照。只保存引用、元数据及展示配置，不存事件、资源正文或凭据。
- 编辑提交完整配置与读取时的 `base_version`；版本不匹配返回 409，不覆盖最新配置。
- 当前配置更新、历史追加、关联 Catalog 的 Agent/运行时/分类/展示字段同步在同一事务提交。
  目录保留身份、上下架状态及其他运营字段。无关联时不创建目录项；任何冲突全部回滚。
- 员工目录与新建 Session 使用同步后的最新配置。既有 Provider Session 保留创建时运行时，
  不在对话中途替换资源。模版版本不锁定 Provider 的 Agent 版本。
- 模版列表不显示模版版本，API 返回版本用于并发校验。详情「版本管理」提供只读历史列表与
  快照查看；历史按版本倒序分页，包含当前版本，配置与保存时间读取对应不可变记录。
  管理员可显式确认应用历史配置，通过同一更新事务追加新版本，不能降低当前版本号或覆写历史；
  应用仍以当前 `base_version` 防止并发覆盖。审计员只能读取，员工不提供版本选择。

## 理由

同一 SQLite 事务保证不会出现模版已更新而员工目录仍是旧配置的半成功状态。不可变快照保留
真实保存记录，乐观锁保护多管理员编辑。复用既有 Catalog 和 Session 创建流程，避免引入另一套
员工会话模型或假设 Provider 支持会话中途替换运行时。

## 后果

历史记录随保存次数增长，需要未来根据实际规模设计保留策略。模版更新会同步已关联目录的
名称、分类、展示及运行时字段；其余运营字段与可见状态保持独立。更新失败不追加版本，也不修改目录。
上下架仍独立经过计划和显式确认，模版编辑会使旧上架计划失效。
管理员删除整个模版时，经删除计划与显式确认统一清理当前配置、全部历史和关联 Catalog；
不单独修改或删除某个历史快照，既有会话与 Provider 资源保留。

## 备选方案

- 仅覆盖当前记录并递增数字：无法保留对应版本配置，不满足保存历史的语义。
- 每次编辑创建新的 Catalog：会改变员工入口与会话关联，产生多余条目。
- 异步同步目录：引入可见延迟与失败补偿，现有同库场景无需承担该复杂度。
