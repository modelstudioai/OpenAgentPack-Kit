# ADR-0010：本地成员目录与创建凭据

> 创建与密码存储决策继续有效；“暂不开放登录”的阶段边界已由 ADR-0011 扩展。

## 背景

体验页已有按 `subjectId` 隔离的会话与 Credits，但缺少真实成员目录。首期按管理端创建用户
流程提供本地账号，后续再接体验页登录与成员分析。此决策补充 ADR-0003 的 SQLite 数据范围。

## 决策

1. 成员是 Kit 自有对象，使用稳定 `member_id`。用户名统一小写且唯一；显示名称与邮箱是
   资料字段，不作为身份主键。成员不会自动获得管理员权限，也不是百炼 Provider 用户。
2. SQLite 保存成员资料，以及随机盐、scrypt 参数和密码派生值；不存密码明文，不存
   Provider 凭据，不新增事件正文存储。加密派生仅在 server service 内执行。
3. 管理员创建时可以选择自动生成或自定义密码。自动密码使用密码学安全随机数，遵循与
   自定义密码一致的规则，仅在创建响应中返回一次；列表不可查回。自定义密码不回传。
   创建响应禁止缓存，前端仅在当前成功页内存中显示；离开页面后清理，不写 localStorage、
   URL、日志或审计。审计只记录创建主体与成员 ID。
4. 首期仅实现成员列表、搜索、分页与创建。现有 `ADMIN_TOKEN` / `auditor` 闸门继续生效。
   不开放成员密码登录、不签发成员 token、不改变匿名 / JWT 解析、不自动合并历史匿名身份。

## 理由

复用已有服务、SQLite 迁移和管理端 API 基础设施，可先交付完整的创建与查询流程。将本地
成员资料与 Provider 分开，既不会将账号创建误当云端资源变更，也保留后续登录和用量关联的
稳定标识。密码派生与单次展示避免把成员目录做成可读回的凭据仓库。

## 后果

- 管理员可以创建成员，但该账号在体验页登录入口实现之前不能用于登录。界面与文档必须
  说明此阶段边界，不能以“创建成功”宣称登录已打通。
- 数据库备份包含认证派生值，按应用私有数据保护；不允许在普通 API 中暴露这些字段。
- 后续登录、密码重置、停用和会话撤销需另行实现并补验收，不以本期创建接口替代。

## 备选方案

- 企业 SSO / 通讯录同步：用户明确暂缓，后续在实际身份合同明确后接入。
- 只有前端演示列表：无法持久化、无法支持后续成员身份关联，不满足创建用户的目标。
- 保存密码明文或可解密密码：不采用；管理员没有反查成员密码的业务需要。
