# ADR-0018：目录链路退役与显式凭据

状态：已接受（2026-11-12）。

## 决策

Kit 只交付 YAML 资源批次。移除目录 Project API、按项目声明创建调试的入口、Build、源码版本和目录恢复分支。
SDK 自身的目录与 CLI 能力保留；模版版本、远端资源引用及既有 Session 不依赖旧目录链路。

- 独立批次服务负责身份、暂存、确认和 Operation；gateway 使用公开的对象解析、Plan、state 与执行接口。
- 删除 KIT_PROJECT_DIR 及历史主项目 MCP 候选来源，候选来自本批声明及显式填写、导入的配置。
- Provider 配置显式传入 SDK。Vault 值只在本批内存保管，通过私有函数解析到配置副本；不写全局环境变量。
  配置加载仍可读取部署环境。数据库、YAML、state、回执和错误不保存明文凭据。
- 选择直接退役，不提供一次性目录恢复或转换工具。追加迁移原样归档目录批次及关联文档，移出活动表、释放唯一名额。
  原磁盘目录和文件保持不动；归档仅供人工核对，运行接口不暴露旧批次，也不自动重放远端操作。
- 保留 ADR-0017 的确认、SDK state 检查点、完整成功证明、最小回执、独立上传暂存和未知结果禁止重发合同。
  服务重启后未发布密钥须重新输入；完整成功后的收尾不要求密钥值。
- 新建和编辑仍按现有复制语义创建新 Agent，不增加同 ID 升版。

## 后果

这是控制面接口的破坏性删减，旧 Project 客户端须改用资源批次 API 或直接使用 SDK/CLI。
旧项目来源的调试 Session 元数据保留，后续读取和操作仍使用 Session ID。
本决策替代 ADR-0017 中的目录兼容及普通 Project 保留条款，并替代 ADR-0014 的目录批次实现方式。
