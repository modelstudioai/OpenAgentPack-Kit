# ADR-0012：本地用户组与成员关系

- 状态：已接受
- 日期：2026-10-28

## 背景

管理端已有独立的本地成员目录，需要先提供组织配置，为后续 Agent 授权建立稳定的分组基础。
本期用户明确选择仅实现组管理，不接入 Agent 权限。

## 决策

1. 用户组是 Kit 本地对象，存于当前数据库；不向 Provider 创建或同步组。一个本地成员可属于
   多个扁平组，匿名和外部 JWT 不参与成员关系；组不授予 admin/auditor 角色。
2. 组使用不复用的内部 ID；名称去首尾空格后唯一，改名不改变关联。组表和关系表是两侧管理
   入口共用的唯一事实来源。新建组为空，升级不自动归组。
3. 关系更新采用明确的增删集合，在同一事务里验证全部引用并执行；不将分页候选或当前页
   选中值视为完整成员集。重复增删幂等，新增和移除集合不能包含相同 ID。
4. 删除组通过 plan、展示影响、显式确认执行；确认绑定管理员和组版本，期间成员关系或
   组资料变化必须重新审阅。删除只清理组及关联，用户账号与历史数据保留。
5. 本期分组不改变 Agent、会话、附件、用量或 SSE 权限；后续授权需要独立明确生效范围、
   撤权策略和历史会话关联，不能以已有用户组配置推断权限已经生效。

## 理由

稳定 ID 和独立关系表允许后续授权引用组而不依赖可变名称。增量事务可以安全处理跨页选择，
两侧入口不会维护两套名单。版本绑定的删除确认保证用户看到的影响面仍然有效。

## 后果

原界面允许管理员从组详情或用户列表维护同一份关系，分组只在管理端展示；登录合同保持不变。
本功能不需要 Cloud 凭据或 SDK 扩展；验收使用独立 SQLite 和 Mock 全栈。

2026-11-11 按产品要求移除管理端用户组界面，成员管理直接展示成员列表；旧组链接回到成员列表。
上述控制面合同、现有组和成员关系继续保留，不再提供组详情或用户列表中的关系维护入口。

## 备选方案

- 将组信息写进登录令牌：成员变更容易与旧令牌不一致，也会提前混入授权语义，本期不采用。
- 用当前页多选值完整覆盖名单：会误删其他分页关系，采用显式增删集合。
- 同时实现 Agent ACL：用户明确分期，本期不改体验端访问行为。
