本教程在**Mock 模式 + 成员登录**下走完 kit 的完整闭环，不需要百炼凭据、不产生任何云资源。
跟着做完，你会拥有：一个已上架的 Demo Agent、一个可登录的成员账号、一轮带工具与文件的
对话，以及一份可查看的成员用量。

## 30 秒速览

```bash
pnpm install && pnpm setup
[ -f .env ] || cp .env.example .env     # 生成 ADMIN_TOKEN 填进去（见快速开始）
# .env 确认：KIT_GATEWAY=mock、KIT_AUTH_MODE=member、KIT_DATA_DIR=.scratch/local-demo/data
pnpm dev server web console
```

| 端 | 地址 | 登录 |
| --- | --- | --- |
| 管理端 | http://localhost:5174 | `.env` 的 `ADMIN_TOKEN` |
| 体验页 | http://localhost:5173 | 第 3 步创建的成员账号 |
| kit server | http://localhost:8787 | 凭据与数据只在这里 |

主线五步：**① 建模版 → ② 预览调试并保存 → ③ 上架 + 建成员 → ④ 成员对话 → ⑤ 看用量与限额**。
每步结尾有「成功标志」，对不上就查[第 6 步排障](#第-6-步排障与清理)。

<Callout title="Mock 意味着什么">
Mock 提供 `assistant（agent_mock_assistant）` 等远端候选智能体：流式回答、工具调用、
工具审批、artifact 文件都是固定模拟（触发词见第 5 步），**不能**验证提示词修改效果。
会话事件在进程内存（重启即清空）；模版、成员、目录、用量快照在 `KIT_DATA_DIR` 的 SQLite。
</Callout>

## 第 1 步：创建模版（向导：选择配置 → 预览调试）

管理端登录后默认进入「智能体管理」（模版列表）。点侧栏**智能体资产 → 创建智能体**
（或列表页右上角「创建智能体」），进入两步向导。

**① 展示配置**（决定体验页长什么样）：

| 字段 | 本次 Demo 填法 |
| --- | --- |
| 智能体名称 | `Demo 助手`（重名就换一个） |
| 分类 | 通用 |
| 描述 | 通过完整 Demo 体验对话、文件与成员用量。 |
| 开场白 | 你好，我是 Demo 助手。一起从第一轮对话开始吧。 |
| 示例问题 | 每行一条：`帮我整理一份工作周报`、`给我一份报告 artifact` |

**② 基础配置**：点「导入现有配置」→ 在「选择配置」抽屉里点该行的
「选择智能体 assistant（agent_mock_assistant）」→ 打开的「智能体详情」抽屉里核对版本与
模型（需要换版本点「切换版本」）→ 点「**确认选择**」。导入会带入模型、工具与审批策略；
环境留空即用智能体默认环境，文件 / 记忆库 / 密钥库本次留空。

填完点底部「**下一步：预览调试**」。只导入已有远端配置时**不需要发布**；若改为新建
智能体或运行资源，会先存入一次性批次，走完校验 → Build → Plan，并在确认弹窗里显式
确认后才发布（取消不执行）。

**成功标志**：进入预览步骤，页面展示所选智能体并自动建好一个管理员调试会话。

## 第 2 步：预览调试并保存

在预览对话框输入 `给我一份报告 artifact` 并发送：等流式回答结束、状态条显示「空闲」，
回答下方会出现 `mock-report.md` 产物按钮（点击即下载）。这一步验证了对话链路和文件链路。

点「**保存智能体**」，在确认弹窗点「保存」，回到模版列表。

<Callout title="继续调试与版本">
列表行「调试」会打开详情调试 Tab 并自动建会话；切走或离开页面会自动清理该临时会话。
详情「版本管理」展示已保存的配置历史（只读），不是源码恢复入口。管理员调试会话按管理员
身份隔离，**不计入成员用量**。
</Callout>

**成功标志**：列表里能重新打开「Demo 助手」，状态为未上架。

## 第 3 步：上架，并创建成员账号

**上架**：模版列表该行点「上架」→ 弹窗「确认上架」审阅影响 → 点「确认上架」。
系统按模版自动建立关联的 Catalog 条目（无需手工建目录），状态变为已上架。
下架 / 删除模版同样有确认弹窗，且**不会**删除 Provider 资源或已有成员会话。

**建成员**：侧栏**配置 → 成员管理** → 「创建用户」：用户名 `demo-member`、显示名
`Demo 成员`、邮箱留空、保持「自动生成密码」→ 「立即创建」。成功页的初始密码**只展示
这一次**，复制保存（下一步登录要用）。

![创建本地成员：用户名、显示名与密码生成方式](/shots/local-demo/07-member-create.png)

*创建用户页：用户名统一小写唯一；也可自定义密码（需满足强度提示，且不回显）。成员只存
Kit 本地库，不在百炼建账号；当前无自助注册 / 重置 / 停用 / SSO。*

**登录体验页**：打开 http://localhost:5173 ，用 `demo-member` + 初始密码登录。
登录有效期 8 小时（刷新可恢复，关标签页通常需重登）；切换成员会清空页面旧数据；
网络失败只重试、不自动降级匿名（匿名演示需显式 `KIT_AUTH_MODE=anonymous`）。

![体验页成员登录：使用管理员创建的本地账号](/shots/local-demo/08-member-login.png)

**成功标志**：登录后广场能看到「Demo 助手」卡片。

## 第 4 步：成员对话 → 管理端看用量

**对话**：广场点「开始体验」进入聊天页（地址带 `?agent=<目录 ID>`）。左侧全局侧栏是
新聊天 / 搜索 / 按智能体分组的会话目录 / 最近会话与广场入口；右侧面板展示当前 Agent
信息、技能与 MCP、工具审批策略和产物区。点示例问题会**直接发送**；等回答结束、右上显示
「空闲」。切「新聊天」再从侧栏选回原会话（或刷新后选择），历史应完整恢复。

![成员登录后的广场：发现已上架的 Demo 助手](/shots/local-demo/09-web-plaza.png)

![成员对话：会话目录、Mock 回复与右侧 Agent 信息/工具/产物面板](/shots/local-demo/10-web-chat.png)

**用量**：管理端**统计 → 用量**，把「用量视角」切到**成员用量**（默认是模版用量），
搜索 `Demo 成员` → 该行「会话明细」进入详情：累计输入 / 输出 / 缓存读取 / 缓存写入
Token、执行时长与会话时长，每项带已采集会话覆盖数；下方是按会话的用量明细。
「刷新用量」强制重新采集（先展示旧快照再后台更新）；列表页「刷新列表」受 60 秒缓存约束。

![管理端成员用量详情：限额设置、累计 Token/时长、覆盖数与会话明细](/shots/local-demo/12-member-usage.png)

*指标来自 Provider 会话详情的累计统计（Mock 每轮累加固定演示值），不是账单口径；
不含管理员调试、匿名与外部 JWT 会话。删除会话会保留已采集的用量快照（明细标「已删除」）。*

**限额**：成员用量视图的「默认限额」设置区改全局默认（Token 与执行时长可单填或同填，
留空 = 不限量，0 = 禁止新增消耗）；成员行 / 详情「设置限额」做个人覆盖，「恢复默认」
回退跟随默认。按 UTC 月重置，任一启用指标到限即拒绝后续发送（运行中的一轮可能继续消耗）。
成员侧在体验页「我的用量」看本月已用 / 剩余 / 重置时间；超限保留草稿并禁用发送，管理员
提高限额后点「重新检查额度」恢复。匿名 / JWT 身份仍走兼容 Credits，本地成员不受其限制。

**成功标志**：成员能恢复历史；管理端成员用量里能看到该成员的累计指标与明细。

## 第 5 步：按需体验更多能力

- **工具审批**：发送 `approval artifact`，会出现两个待审批工具调用：逐项看参数后
  「允许」或「拒绝」一步直提；全部处理完才继续生成。
- **附件**：新会话里上传文件再发送（文件随建会话挂载）；已有会话加附件会给出
  「新建会话并挂载」出口——Provider 没有中途追加挂载接口。
- **H5**：体验页窗口缩窄到 390px，检查移动布局与会话抽屉。
- **真实 Cloud**：`.env` 改 `KIT_GATEWAY=sdk` + 凭据 + 独立 `KIT_DATA_DIR` 后重启；
  向导里可选当前 workspace 的远端 Agent 及版本，或新建资源（经批次计划与显式确认发布）。
  发布前逐项核对计划与 workspace 模型可用性；真实发布**会创建云资源**。

![Mock 工具审批：逐项审阅参数并作出决定](/shots/local-demo/13-tool-approval.png)

## 第 6 步：排障与清理

| 现象 | 检查与处理 |
| --- | --- |
| 启动提示 Node 版本不足或依赖入口缺失 | 按[快速开始](/docs/quickstart/#安装并启动)检查环境；等启动器构建完成 |
| 想跑 Mock 却显示 `gateway=sdk` | 改根 `.env` 的 `KIT_GATEWAY=mock` 并重启（.env 覆盖 shell 同名变量） |
| 体验页停在登录页 | 用成员账号登录（不是 `ADMIN_TOKEN`）；成员要在同一后端的管理端创建 |
| 登录后广场为空 | 检查模版已上架，且两个页面连的是同一个 server（看终端打印的端口） |
| 向导「下一步」一直灰 | 基础配置必填未满足：导入后核对模型是否带入；新建资源时补齐必填项 |
| 保存 / 发布提示计划过期或 `Build is missing or stale` | 批次已变化：回配置页重新准备计划，不要复用旧确认令牌 |
| Mock 重启后历史无法恢复 | 会话事件在内存；成员 / 模版 / 目录仍在 SQLite，新建会话继续 |
| 数据看起来串了 | 核对 API 地址与 `KIT_DATA_DIR`：Mock 与 Cloud 服务使用独立目录 |
| 端口占用 | 以终端打印的实际端口为准；确认占用进程属于本仓库再停重复实例 |
| Cloud 返回 `InvalidApiKey` / `Endpoint.AccessDenied` / `AccessDenied.Unpurchased` | 凭据有效性、与 workspace 匹配、模型是否开通；或切回 Mock 继续演示 |

清理顺序：① 删本次会话（先审阅确认；要留用量先看明细）→ ② 模版列表下架 / 删除 Demo 模版
（关联目录同步处理，远端资源保留）→ ③ **用过真实 Cloud 时**按发布回执在 Provider 控制台
清理本次新建资源 → ④ 停服务；确认要重置演示数据再删 `KIT_DATA_DIR`（里面含成员、登录、
限额与用量快照，不只是目录）。真实项目的 `.openagentpack/` 在云资源清理完成前不要删。
