# apps/console — 管理端

## 不变量

1. **控制面身份使用 ADMIN_TOKEN**（v1）；令牌只存本机 localStorage，不进 URL/日志。
   凭据绑定规范化后的完整 `apiBaseUrl`（含路径前缀），仅对对应目标发送；新目标先显示登录，
   不继承已有服务的令牌。旧无目标令牌仅允许迁移到当前页面 origin 的根后端。
2. **破坏性/状态变更必须 AlertDialog 确认**（上架/下架/删除/apply/publish），且先展示影响面。
   模版删除按明确产品要求例外：正常正文仅为「是否删除该模版」，后台计划与显式确认闸门保留。
   模版调试沿用用户已授权的自建临时调试会话自动清理：切换模版/版本或离开页面时无需再次
   弹窗，仍调用删除 plan 并携带确认令牌；授权只覆盖本页面拥有的根 Session。
   确认层的组件实现允许 antd Modal（见下方「UI 组件栈」节），交互合同不变。
3. **不假设同源**：渲染 App 前读取公开 `/api/config` 并校验协议，按宿主注入 > `?api=` >
   `apiBaseUrl` > 当前 origin 确定地址。初始化失败只展示重试入口，不发送管理请求。
   HTTP 与 Operation SSE 共用 SDK Request，每次请求动态读取管理员令牌；配置请求不带令牌。
   本地同源仍可走 Vite proxy，跨域部署需由 server 显式配置 CORS 白名单。
4. **资源发布及模版历史应用必须展示 diff 后确认**（alertdialog 语义；antd 迁移页可用
   antd Modal，见「UI 组件栈」节）。资源操作使用 YAML 批次，不提供目录 Build 或源码版本入口；
   模版配置历史由 Kit 管理。
5. **「用量」展示本地成员的 Session 累计用量**：按成员搜索、分页，展示含已删除会话的
   Session 数、四项 Token、执行/会话秒数、逐指标 coverage、采集状态与时间。列表刷新仅
   调度当前页并遵守 TTL；详情复用成员用量页，支持 Agent 筛选、明细分页与强制刷新。
   不提供全局总计或 Credits 政策、审批、override、加油包入口。页面提供默认与个人月度
   Token / 执行时长限额，成员详情同时展示不受 Agent 筛选影响的全成员月度状态。设置和
   恢复默认先展示差异并确认，auditor 只读；未知指标不能显示为零。

6. **页面采用 Browser History 路径路由**：URL 是当前页面与已保存资源定位的事实来源；
   `features/navigation/console-route.ts` 统一解析/生成，`console-router.tsx` 统一导航与历史遍历。
   页面、详情与主要 Tab 不再用独立内存状态选择；保留 `?api=` 等宿主参数，认证后恢复原路径。
   侧栏、返回按钮及浏览器前进/后退均遵守忙碌锁定和未发布批次退出确认；确认前不卸载页面。
   表单、密码、凭据与确认令牌不进入 URL/history.state。新建/编辑的预览依赖内存草稿，
   直接访问或刷新缺少草稿时，新建回创建方式选择页，编辑回配置步骤，不能仅因 URL 自动发布资源。
   路由表与生产部署回退要求见 `docs/architecture.md`。

7. **管理业务与 React 编排归 console**：AdminClient、成员用量控制器、Operation 观察器以及
   `useAdminQuery`、`useAdminMutation`、`useAdminOperation`、`useMemberUsage` 位于
   `src/lib/admin/`（ADR-0025）。固定管理路由和恢复流程不得放回 SDK；通用查询、写入、
   快照订阅和协议帧读取分别复用 `@openagentpack/kit-sdk/state` 与 `/providers/kit` 公开入口，不复制实现或导入私有源码。
   Operation 只重连观测，不重发执行；迟到 GET 不覆盖 SSE，终态不回退，释放后丢弃回调。

## UI 组件栈（antd 准入，ADR-0015）

1. **antd v6 仅在 `apps/console` 使用**（原生支持 React 19，不引入 v5 patch 包）。
   源码 import 边界由 dependency-cruiser `antd-console-only` 强制，依赖声明由
   `pnpm check:no-inner-deps` 的 antd 白名单强制；在 console 之外引入 antd 触发根
   AGENTS.md 执行红线。
2. **组件决策阶梯**：新代码 antd 优先（表格、表单、树、上传等重控件直接用 antd）；
   两类例外——对话链路组件（消费 SessionEvent/消息分片/会话状态，或走
   ChatProvider 与 SDK 功能 `/hooks` hooks 合同：Chat、MessageList、Sender、审批卡、ToolCallCard、
   SubAgentCard、ArtifactCard 等）一律 `@openagentpack/kit-chat-ui`，例外需在 PR 记录
   理由；页面上已存在且好用的 chat-ui 用法不强制替换。
3. **迁移以页面为单位渐进进行**：摸到哪个页面用 antd 重写哪个页面；同页两套表格/弹窗
   体系是待收敛状态，不是目标形态。对话区域（模版调试 Tab、向导预览步骤的对话组件）
   不随页面迁移。
4. **破坏性操作的交互合同不变**：先展示 plan diff、显式确认、无旁路仍是协议层闸门；
   「AlertDialog 语义」放宽为「模态 + 焦点受管 + 显式确认」，允许 antd Modal 实现，
   优先复用 chat-ui AlertDialog。
5. **主题归口**：antd token 统一在 `src/lib/antd-theme.ts` 经 `ConfigProvider` 配置
   （首次引入 antd 时建立），管理端直接使用 antd 默认主题、不做色板定制（黑白灰中性板
   仅适用于员工端 workspace 外观）；antd 组件内部样式豁免
   「Tailwind 工具类 + `theme.css`」要求，页面级布局样式仍走 Tailwind 工具类；
   chat-ui `theme.css` 与 antd 主题互不引用；不得在组件内散落 antd token 覆盖或用
   `className` 微调 antd 内部样式。
6. **antd 与 Tailwind v4 preflight 共存约定**：Tailwind 的 reset（button cursor 为
   default、border 样式等）会干扰 antd 组件外观；修复统一写入 antd 主题配置文件旁的
   全局修正层（加载顺序 Tailwind 在前、antd 在后），禁止在页面组件里散落修补；新增
   怪癖时补进本节清单。已知怪癖：antd v6 的 `--ant-*` css-var 只挂在组件根作用域类
   （`.css-var-*`）上，非 antd 元素（kit-chat-ui、Tailwind 工具类、body）读不到，
   `var(--ant-color-*)` 会静默失效（如白底白字的隐形确认按钮）；镜像定义归口在
   `src/styles.css` 的 `:root`，定制 antd 色板时两处同步。
7. **不引入 `@ant-design/x`**：对话能力一律走 kit-chat-ui；antd 仅服务于管理端
   CRUD 重控件；不为 console 产物设 bundle 门禁。
8. **antd 用法基线**：表格操作列与行内次要动作用 link 按钮（`<Button type="link" size="small">`），
   危险动作加 `danger`，不为此类动作使用描边或主色按钮；页面级主操作（新建、保存等）
   才使用 `type="primary"`。页面数据加载失败用 `Result status="error"`，空态用 `Empty`，加载态交给
   Table `loading` / `Spin`；表单提交等一次性错误用可关闭的 `Alert type="error"`。
   语义色与需要脱离组件直接着色的场合一律消费 antd css-var（如 `text-[var(--ant-color-error)]`），
   不在业务组件里新增色值常量。

## 加一个新管理页面时

「日志」页沿用 `/operations` 路径，通过 `useAdminQuery` 读取操作审计分页，每页 20 条，不提供刷新按钮。
仅查询当前管理身份的智能体新建、编辑、删除、上架、下架及品牌配置更新操作，展示时间、中文操作类型、对象名称与 ID，不展示操作人；
名称使用审计快照，历史日志缺名显示目标 ID，旧 detail 数组/null 可读。加载失败显示 Result 与重试。
其他动作不写入操作日志，历史非白名单记录由服务端同时从列表和分页总数中过滤。

管理端使用 `features/navigation/console-layout.tsx` 统一外壳：桌面左侧常驻菜单，主内容
独立滚动；小于 768px 时从左侧抽屉选择页面。内容区全宽不设最大宽度，页面内容由外壳统一
包在 antd Card 内（经典后台风格）；页面自身不再套白底卡片容器，卡片内分区靠间距与
`bg-neutral-50` 内衬区分。两种形态共用菜单，只挂载一份导航；页面切换
关闭抽屉，跨到桌面关闭模态层。菜单保留当前页语义和操作期间的导航锁定。
「智能体资产」下按顺序展示「创建智能体」「智能体管理」两个子菜单；父项和「智能体管理」均进入模版列表，页内标题为「智能体管理」。
「系统」下提供菜单「配置」页（`/branding`，页内标题「品牌配置」），读取 `GET /api/admin/branding`，用 antd 表单维护员工端产品名称与 Logo；默认「上传图片」，可切换「填写 URL」。上传支持 PNG/JPEG/WebP/SVG（≤512KB），URL 只接受以单个 `/` 开头的本站路径或 http(s) 地址，留空回退首字母。保存后提示员工端刷新生效，auditor 只读；不要改回 `.env` 或构建时注入。
创建页初始不展示表单，仅提供「导入现有配置」「从零开始创建」；前者打开「导入预设包」抽屉，后者展示原有表单。
导入成功后回填并展示表单，取消或失败保留初始选择页。从零创建的表单不提供页头「导入预设包」，导入回填后的表单保留该入口供重新导入。
旧 `/preset-packs/import` 作为已移除路径回到模版列表。
导入抽屉首个模块为「智能体」，复用 `useRemoteAgents` 查询完整远端列表，
以 antd Table 每页展示 10 条名称、ID 和版本；包含当前凭据可见的全部 MA Agent，不按 Kit 模版、上架状态或协调模式过滤，
不混入本地草稿。Provider 的游标遍历和去重仍由 gateway 负责，页面只分页展示。加载使用 Table loading，
失败使用 Result 并提供重试，空列表使用 Empty；不展示通用页脚说明。
智能体列表支持单选；选中后通过 `useAdminQuery` 调用预设包资源发现接口，自动获取该智能体的全部可见会话及当前资源引用，
下方只展示按类型分组的运行时资源，不展示关联会话列表或会话 ID；每组以 Table 每页展示 10 条。
同类型资源按底层资源 ID（文件/记忆库/环境/密钥库 ID，缺省回退运行时资源 ID）跨会话去重；
同一资源的不同挂载路径、访问权限和来源合并保留，仓库资源保留脱敏 URL。缺少 ID 时不跨会话误合并。
资源列表不提供「查看配置」操作、checkbox 或全选；点击整行打开对应资源的详情 Drawer，聚焦行后 Enter/空格同样打开。
加载成功后以底部「确认选择」选中，关闭或取消不选中。选择状态列中「未选择」使用 antd 默认中性色 Tag，「已选择」使用 success 绿色 Tag 并提供「取消选择」，取消不触发行点击或键盘打开详情；加载或提交期间行不可激活。
环境、文件、记忆库、密钥库均使用此流程，已选项标记状态并可取消选择；跨类型及翻页保留选择，展示已选总数。
环境组单选，确认另一个环境才替换原选择，取消查看保留原环境；文件、记忆库、密钥库分别最多多选 10、8、10 个。
分组标题展示选择规则。多选达到上限仍可查看其他资源，但详情确认禁用并提示先取消其他选择；代码仓库和未知类型仅展示，不能关联。
选择仅保存在当前智能体页面内，切换智能体清空；确认选择只确定待导入资源，不触发 Provider 写操作。
「导入」经 `useAdminMutation` 调用 `presetPacks.preview` 只读核验，不保存预设包；加载或提交中禁止修改选择与导航，失败保留选择并显示可关闭的 Alert。
提交只含 Agent ID、所选版本与资源身份，服务端重新发现并核验资源；成功后在内存中回填创建页，不将配置放入 URL/history.state。
保留固定版本、文件路径、记忆权限与密钥库引用；不直接创建会话、保存模版或发布。
创建方式选择页的「导入现有配置」与导入回填后表单页头的「导入预设包」共用 antd Drawer，由 `PresetPackSelection` 展示完整远端列表和运行时资源。
按名称/ID 搜索、每页 10 条，单选智能体后查看按类型分组、按 ID 去重的资源并多选；不使用本地已保存预设包列表。
列表和资源各自处理加载、空态、失败重试；读取失败或切换选择期间禁止导入，不复用旧结果，浏览或取消保留原表单。
回填保留当前展示名称、分类及文案，仅替换基础配置和运行时资源；已有资源配置或未发布批次时先用 ConfirmDialog 明确确认。
确认后重新初始化资源草稿并沿用已有批次清理，不重复弹离页确认；同一预设包也可重新导入。
导入配置与展示字段均仅保留在当前创建页内存中，不新增保存记录，刷新回到创建方式选择页；历史 `?preset=<id>` 仍读取旧包并直接展示回填表单。
请求 key 和子组件身份绑定 Agent ID，切换立即清除旧结果；错误可重试，部分失败必须显示 Alert，
不得将已读取子集显示为完整资源。发现接口不读取正文；仅用户显式查看资源配置时读取既有只读配置接口。
环境复用 `EnvironmentDetailView`，密钥库复用 `TemplateVaultDetailView`，记忆库复用 `TemplateMemoryEntryList` 展示已读条目，文件仅展示元数据和挂载配置；不提供文件正文、事件正文或密钥值查看入口。
记忆条目无法完整读取时，通过未归档记忆库目录重新核验原库，展示名称及未完整读取提示，允许确认关联引用并重试读取条目；不伪造空条目。
配置或记忆库摘要未加载、元数据不可读、缺少 ID、文件不可用或不支持的类型不能确认选择；其他详情失败仍禁止选择并提供重试。
详情关闭取消在途读取，查看期间锁定外层选择和关闭操作。
基础配置「导入现有配置」在查看远端智能体详情时预读关联运行时资源，检测中「确认选择」加载且禁用，检测失败可重试。
智能体详情的「确认选择」将有效检测结果随 Agent 交给创建页；配置选择抽屉关闭后直接显示提示，不重复发起发现查询。
只有确认选择才显示提示，取消智能体详情不改原配置；失败结果不作为有效预读数据，选择后仍可重试或取消检测。
有结果时用 Modal 提示「检测到当前配置有关联的运行时资源，是否直接使用？」；确定并关闭提示后才打开资源多选 Drawer，避免焦点层重叠。
`template-agent-runtime-resources.tsx` 复用预读结果及 `PresetPackResourceSelection`，主动重读或提交时仍重新核验；默认不选，至少确认选择一项才能使用。
「使用所选资源」与「取消」并列放在资源选择 Drawer 的 footer，滚动列表时保持可见；失败反馈同样挂载到 footer 的按钮上方，长列表顶部提交也能看到原因并保留选择重试。提交状态与校验仍由资源选择组件持有，不复制按钮状态或提交逻辑。
只关联已确认的引用，不重建基础表单；相同 ID 保留现有路径、权限和草稿，其他已选资源保留，选择不同环境时替换该环境。
先校验合并后的文件/记忆库/密钥库数量及文件路径冲突，再整体回填；失败保留资源选择和原表单。
检测无资源不弹提示，失败及空的部分结果展示重试/取消；检测与选择期间锁定其他配置及导航，取消或完成后解锁。
初始回填、单独切换版本、本地未发布 Agent 与页头导入不触发重复检测；卸载时取消查询，旧响应不能弹出新提示。
独立「上架目录」页面和菜单已移除，旧 `/catalog` 地址进入模版列表；上下架在模版列表操作。
`features/catalog/` 仅保留模版和用量仍在使用的资源查询、选择器、展示字段及校验，不恢复独立目录页。
旧项目工作台页面已移除，根路径及旧 `/project` 子页面统一进入 `/templates`，清除旧 `agent`
定位参数并保留 `?api=` 等宿主参数；不得因此请求旧工作台数据或修改项目资源。
模版调试由新建/编辑向导的预览步骤与详情页的调试 Tab 提供，复用 `TemplateDebugPreview` 和员工端组件。
创建、发送、审批和执行期间锁定导航；清理失败在 App 中保留重试入口。
旧模版缺少 `agent_version` 时不从展示快照推导绑定，未选环境时省略覆盖。
「创建智能体」进入 `features/templates/create-template-page.tsx` 的创建方式选择页；选择从零创建或成功导入后进入新建模版向导，页内标题为「创建智能体」。新建与编辑均包含「选择配置 → 预览调试」两步。新增资源使用独立 ResourceDraft，当前页面内的 Agent、环境、文件、记忆库、
密钥库及 Skill 上传共享同一批；声明与 SDK state 仅属于当前批次。远端配置无待处理批次时直接进入预览调试。
新批次通过 `AdminClient.draftResources` 操作当前 YAML，经 SDK 校验和 Plan，复核 revision/有效期并用确认弹窗列出本批次影响，
显式确认后执行 Publish。发布中锁定导航和修改，进度失败仅重连原 Operation，结果不明禁止重发。
